# Keyboard and mouse

How to use the interface: the keys, the footer, the header's indicators, dialogs and navigating control by control.

[← All documentation pages](README.md)

The UI is monochrome (Settings → Appearance: grey, amber or phosphor ink, UI scale, key hints; saved per computer in `machine.json`).

The layout is made for a 1512 × 915 px window (14" MacBook at its default display setting). On smaller screens, down to 1280 × 720, use Settings → Appearance → UI scale → **Fit window**: it picks the largest scale at which every page fits without scrolling (about 70 % on 1280 × 720). Pixel sizes are CSS pixels, which macOS and Windows scale with the display setting. Colour only appears where it carries information: the hue/saturation scales and the output colours.

Everything works without a mouse — on the General, Dimmers and Control Desk pages one control is always selected, on the other pages the keys move a highlight from control to control (see below). The footer lists the keys and mouse actions for the control under the mouse, with the keyboard focus (Tab) or selected with the navigation keys, with a short explanation of what it does. Every control, label, status indicator and panel has one; a control without its own tip shows the one of its row or panel:

| Key | Action |
|---|---|
| W / S | move the selection up / down a row |
| A / D | move the selection left / right |
| ↑ / ↓ | change the selected value (Shift = fine) |
| ⏎ | press the selected button, load the selected scene (Shift + ⏎ = save) |
| Esc | cancel a pending hue / saturation change |
| 1 – 9 | switch page (1 General, 2 Dimmers, 3 Fixtures, 4 Rig, 5 Connections, 6 Fog, 7 Control Desk, 8 Settings, 9 Help) |
| Q / E | previous / next subpage: the tabs of Connections, the channel subpages and Routes of the Control Desk (round at the ends) |
| F | full screen on / off (desktop app; on a Mac it is the system's own full screen, the same as the green button and ⌃⌘F: the menu bar slides in at the top edge, the Dock at the bottom) |
| ⌘ / Ctrl + + − 0 | UI scale up / down (`=` works as `+`, no Shift needed), 0 = 100 % (⌘ on macOS, Ctrl on Windows) |
| ⌘ / Ctrl + S | Save: what the page's Save button does, also while typing in a field |
| Alt, F10 | the drawn menu bar (Windows app): Alt + letter opens a menu; arrows, ⏎, Esc; on macOS ⌘1 – ⌘9 switch pages too |

**The header's indicators** (FPS, audio, midi, dmx, art-net) show a small bubble with details when the mouse rests on one or the keyboard focus (Tab) is on it; Esc closes it, and a click still opens the indicator's Connections tab (FPS: Settings, where the target frame rate is). **FPS** is a perf meter like vvvv's: the time of every frame over the last 10 s, so a frame drop shows as a spike, the engine's own compute time brighter at the bottom, the target frame time as a dashed line, and "38.9 / 40 fps, 3 drops in 10 s" (a drop: a frame over 1.5 × the target time), with the longest frame and the engine's share of the frame time. **Audio**: the input device, its channels and level, and the live bands (columns as in the vvvv patch: each band's own decaying maximum faint, the live value, its own minimum brightest, redrawn every engine frame). **MIDI**: a light for the controller and each MIDI route device that flashes with every message, and the last three messages (type, channel, number, value, the macro they moved); the app sends no MIDI. **DMX**: one row per USB DMX interface (output arrow, status, universe, frames per second, the error), the USB DMX input and the PitchPlease v2 serial output, which has no indicator of its own. **Art-Net**: one row per output target (IP address, universe, frames per second) and per sender the Art-Net input hears (address, universe, packets per second, or quiet). The bubbles only read; a phone or another touch screen gets none (a tap is the click). The frame times come from the engine's ring of the last 1,024 frames (two numbers per frame, `engine/perf.py`), sent over the websocket only while the FPS bubble is open (`perf_subscribe`: the last 10 s, then the new frames every 0.25 s); the band displays get their own feed, `audio_subscribe` (`audio_frame()`, once per engine frame, while a display is open); the other bubbles use the state the UI already gets 15 times a second.

Number fields apply on Enter and keep the focus, so you can type the next value right away (Escape reverts).

**Dialogs block the app underneath.** While a dialog is open (Import Fixture, and the "Unsaved changes" question when you leave a page) the page behind it gets nothing: no page keys, no W A S D, no ⌘ / Ctrl + S, no menu-bar keys, no clicks (a click outside does nothing). Tab goes round the dialog's own controls, **Esc** closes it as Cancel (for the unsaved-changes question: Stay), and the focus goes back to the control that had it. All dialogs share one mechanism (`frontend/src/modal.ts`, `components/Modal.tsx`); ⌘ / Ctrl + + − 0 (UI scale) still work, and on macOS the menu bar's page items wait until the dialog is closed.

**Fixtures, Rig, Connections, Fog, Settings and Help, and the Control Desk's Routes, are navigated control by control** (the footer shows the keys). On Connections, Fog, Settings, Help and Routes the first W / S / A / D (or arrow) highlights the first control; after that W / S or ↑ / ↓ move to the control above / below, A / D or ← / → along a row, and A at the left edge or Esc takes the highlight away. The keys only navigate and never change a value: the highlighted control looks like the selected one on the other pages, and **⏎ starts editing it**: a number or text field takes the caret, a dropdown opens, a slider takes the focus, a button is pressed and a switch or checkbox toggles. While you edit, the keys are text and ↑ / ↓ (or ← / → on a slider) change a value as everywhere (Shift = fine); **⏎ or Esc stops editing** and keeps the value (a number field's Esc drops what you typed first), and W A S D navigate again. A click into a field edits it at once. **Fixtures and Rig** have a list first, which works like a file list in Finder or Explorer: W / S or ↑ / ↓ move the selection to the next fixture type or fixture (they stop at the ends; at the first or last one they carry on to the controls above or below the list), D or → goes into the details, and A at the details' left edge, or Esc, comes back to the list. On the Rig page Shift with the movement keys extends the selection as a range from the anchor (the same rule as Shift + click) and Space adds or removes the current fixture without moving; ⏎ does nothing on the list.

On the Rig page, the **Rig** panel manages the rig file: load another rig from the dropdown, edit the description, Save / Revert, Rename, Duplicate (saves the current state, unsaved edits included, as a new rig and switches to it; the original file keeps what was saved), New (empty rig) and Delete (the active rig; the next one is loaded, the last rig can't be deleted). A rig that comes with the app is marked "shipped"; saving it keeps your copy in your data folder ("modified"), Reset to default deletes that copy, and it can't be deleted. Fixture types work the same way on the Fixtures page. Loading or creating a rig with unsaved changes asks: Save, Discard or Cancel. Edits are live in the engine right away; only Save writes the file. The **Fixtures** panel below it edits the lights in the rig: Add, Duplicate, Remove.

In the fixture list, Shift + click selects every fixture from the one you clicked last (by a plain or ⌘ / Ctrl click) to the one you click now, in the order shown; ⌘ (macOS) or Ctrl (Windows) + click adds or removes a single fixture, and ⌘ / Ctrl + Shift + click adds a range to what is selected. The same with the keys: Shift + W / S extends the selection from the anchor, Space adds or removes the current fixture and makes it the anchor. Several fixtures can be edited at once. A field shows a value only if all selected fixtures share it, otherwise "multiple"; a value you enter applies to all of them.

**Control Desk** (page 7) shows every DMX output channel as a slider: pick the universe (0–3) and one of 8 subpages of 64 channels (the ninth subpage is Routes). The faint bar is what the channel sends now (the footer names the fixture using it). Dragging a channel, or switching it on, overrides it: it then sends the slider value instead of what the fixtures compute; the switch releases it. Overrides are saved (`state/overrides.json` in this computer's folder) and restored on start; while any are active the header shows "N overrides". "Reset all" (with a confirmation) releases every override in every universe.

Hue and saturation apply on mouse release, or once keys / the MIDI knob rest; until then the fader shows the target with a dashed outline.
